## 3. Blood & Sand source methodology

The accepted `blood_sand` strategy treats ordinary Yandex Search visibility and Alice AI visibility as one connected system rather than `SEO first, GEO later`.

Its evidence model separates source provenance instead of inventing one fake universal frequency. Important source types include:

```text
SEED
WORDSTAT
SERP_QUERY
ALICE_INPUT
ALICE_FANOUT_OBSERVED
ALICE_FANOUT_INFERRED
ALICE_SOURCE
WEBMASTER_SEARCH
WEBMASTER_ALICE
CUSTOMER_EVIDENCE
MARKETPLACE_EVIDENCE
```

The canonical data flow is:

```text
registry/input
→ raw evidence
→ normalized observations
→ Query Evidence Ledger
→ derived analysis / decisions
```

For each cluster the strategy keeps four reasons for priority separate:

```text
H = Human demand
A = Alice importance
C = Commercial value
O = Owned-asset value
```

These are not blindly summed into one opaque score.

The final decision is not simply `keyword → article`. ChatGPT chooses the actual page job:

```text
new landing/page
existing-page expansion
FAQ / answer block
comparison / guide
product fact / attribute
supporting content
no page at all
```

## 4. Why this is materially different from an ordinary semantic core

A normal semantic core mainly answers:

> What do people type into search, how often, and how should those queries be grouped?

O-001 additionally asks:

> For the same topic, what job does ordinary Search solve, what job does Alice AI solve, which sources/pages does AI rely on, what additional fan-out/questions appear, and what content/page architecture should the client build to compete in both systems without sacrificing commercial value?

`blood_sand` already produced direct evidence that Search and Alice can solve different jobs for the same root query. Examples in the accepted cross-surface review include:

- a root where Search is strongly transactional while Alice is meaning/history/use-first;
- roots where Search is commercial-first while Alice emphasizes mythology, explanation or suitability;
- broad high-frequency roots whose apparent opportunity collapses after intent contamination is compared across Wordstat, Search and Alice.

Therefore an ordinary keyword list can make a different page decision even when its frequency data is correct.

That observation is real evidence, but it is **not by itself sufficient proof that the premium method improves decisions over a strong ordinary SEO baseline**. That must be tested directly by the mandatory comparative gate below.

## 9. Exact O-001 workflow

```text
1. Intake
   site + region + products/services + commercial goals + existing semantic core + optional competitors/pages.

2. Site/business understanding
   ChatGPT maps the real offer, audience, current page architecture, exclusions and conversion jobs.

3. Human-demand layer
   Bridge Wordstat → GetTop / dynamics / regional-device evidence where decision-useful.
   ChatGPT builds and cleans the ordinary semantic candidate set.

4. Ordinary Search layer
   ChatGPT selects representative roots and decision-useful secondaries.
   Bridge Search measures actual Yandex SERPs in the target region.
   ChatGPT records domains, page types, marketplace-vs-independent composition, informational/commercial job and competitor patterns.

5. AI test-set design
   ChatGPT does NOT send every keyword blindly to Alice.
   It selects queries that resolve real uncertainty: commercial vs informational split, selection/use-case branches, comparison branches, contaminated broad roots, missing questions.

6. Alice observation
   one clean/new conversation/context per root;
   capture answer presence/snapshot;
   capture actual source domains/URLs/page types;
   capture observed fan-out when exposed;
   store inferred fan-out separately;
   invalidate context-contaminated observations instead of forcing them into the conclusion.

7. Evidence merge
   ChatGPT creates/updates the Query Evidence Ledger and keeps provenance for every material conclusion.

8. Decision analysis
   per cluster: H / A / C / O;
   compare Search job vs Alice job;
   identify source/content gaps and commercial fit.

9. Semantic rebuild
   ChatGPT decides for every important cluster:
   existing page / new page / FAQ / comparison / guide / product fact / reject.
   Resolve cannibalization and page-role conflicts.

10. Client deliverables
    AI-native semantic workbook;
    Search-vs-Alice intent-gap matrix;
    source/competitor map;
    page/content architecture;
    priority action plan;
    evidence/methodology notes;
    optional page briefs/content specifications.

11. Post-launch validation
    ordinary Webmaster search performance;
    Alice visibility / SoV / source pages when available through capture/import;
    Metrika behavior/conversion;
    compare before/after and revise page jobs when evidence contradicts the initial hypothesis.
```

## 13. Commercial boundaries

Never promise:

- guaranteed indexing in Alice AI;
- guaranteed inclusion as a source;
- guaranteed SoV growth;
- guaranteed traffic/sales from an AI mention;
- that low Wordstat frequency means low AI importance;
- that high AI importance automatically means a new page must be created;
- that observed Alice source order is a ranking;
- that one AI answer is permanently reproducible.

Promise only what can be controlled and evidenced:

- evidence collection under a declared methodology;
- a transparent semantic/page rebuild based on the evidence available;
- concrete content/page actions;
- before/after measurement where client data exists;
- revision of recommendations when new evidence contradicts the original hypothesis.
