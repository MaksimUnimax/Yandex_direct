# MK03 — GENERAL / CROSS-STEP RULES

Status: **ACTIVE / PHASE 3 METHOD EXTRACTION**

These rules govern the complete MK03 V1 product. Per-step rules may strengthen them but may not weaken them.

## 1. Product identity

```text
MK03 = REAL YANDEX ORGANIC COMPETITORS
     + EVIDENCE-BEARING COMPETITOR PAGES
     + COMPETITOR-DERIVED DEMAND PROBES
     + WORDSTAT DEMAND VALIDATION
     + MATERIAL SEARCH CONFIRMATION
     + CLIENT COVERAGE / GAP CLASSIFICATION
     + BOUNDED STRUCTURAL OPPORTUNITY NOTES
```

MK03 is not a full semantic-core rebuild, not a full target architecture product, not a cannibalization audit, not an implementation TZ and not an AI/Alice audit.

## 2. Yandex-only boundary

Base V1 uses ordinary regional Yandex Search, Yandex Wordstat, the public client site and public competitor pages. Google evidence/conclusions are outside base scope.

## 3. Existing-site V1

Standard required client input is:

```text
PUBLIC SITE URL + TARGET REGION
```

The analyst inspects the current public offer/site. Client-supplied competitor names are optional hints, not competitor truth.

## 4. Baseline sufficiency without silently performing MK01

MK03 needs a representative in-scope discovery baseline sufficient to expose the client's material search jobs and discover real organic competitors.

```text
MK03 DISCOVERY BASELINE != FULL MK01 SEMANTIC CORE
```

Do not rebuild a complete semantic core merely to start competitor discovery. Expand the baseline only when a named uncovered business/search direction prevents defensible competitor or gap conclusions.

## 5. Business rival != organic Search competitor

A domain becomes an MK03 search competitor only through current Yandex evidence for in-scope regional query families.

Client familiarity, offline rivalry, ads or marketplace presence do not prove organic search competition.

## 6. Search claim discipline

```text
COMPETITOR PAGE TOPIC != EXACT QUERY RANKING
TESTED QUERY VISIBILITY != UNPROBED QUERY EVIDENCE
TESTED QUERY VISIBILITY != FULL DOMAIN KEYWORD UNIVERSE
```

Exact query→competitor visibility claims require direct current Search evidence or an explicitly reusable current preserved observation for that exact query/region.

## 7. Competitor page is a seed source, not a ranking database

A public competitor page may expose topics, products, services, use cases or modifiers worth testing. Those become candidate acquisition probes with lineage.

```text
COMPETITOR-DERIVED SEED != ACCEPTED KEYWORD
```

## 8. Competitor presence does not override client business truth

```text
COMPETITOR SIGNAL + WORDSTAT DEMAND != CLIENT BUSINESS FIT
```

Every candidate still obeys frozen client offer, geography and explicit exclusions. Material ambiguity remains HOLD rather than being forced into acceptance.

## 9. Wordstat expansion re-enters the universal normalization/sanitation funnel

Every competitor-derived Wordstat response follows:

```text
RAW OCCURRENCES
→ NORMALIZED UNIQUE IDENTITIES
→ HIGH-CONFIDENCE SANITATION
→ COMPARE WITH EXISTING NORMALIZED POOL
→ NEW_SANITIZED_CANDIDATE | ALREADY_COVERED | REJECT | HOLD
```

Raw competitor occurrences are never appended directly to the analytical result.

## 10. New provenance != new keyword identity

If the same phrase is rediscovered through competitor evidence, preserve the new lineage but do not duplicate the analytical phrase.

```text
NEW PROVENANCE != NEW KEYWORD ID
```

## 11. SERP coverage mode

```text
SERP_COVERAGE_MODE = SELECTIVE_DECISION_SERP
```

Fresh Search is acquired/reused for competitor discovery and for material exact-query, intent, page-type or acceptance decisions. MK03 does not bulk-run Search for every raw Wordstat row.

Unprobed rows may still be semantically/business processed, but may not be labelled Search-confirmed.

## 12. Provider calls require named information gain

Before a new Search or Wordstat call there must be:

```text
NAMED DECISION GAP
+ WHY SAVED EVIDENCE IS INSUFFICIENT
+ HOW THE RESULT CAN CHANGE THE DECISION
+ ALLOWED ACCESS / COST STATE
```

Useful provider evidence is persisted before further material acquisition.

## 13. Stop on diminishing information gain, not fixed counts

There is no universal required number of competitors, pages, seeds or Search rechecks.

Stop expansion when additional evidence mostly repeats known normalized directions, returns already-covered demand, creates off-scope noise or cannot materially change a client decision.

## 14. No hidden reverse-domain dependency

Base V1 must be executable without Semrush/Ahrefs/reverse-domain visibility databases. Such data may be optional enrichment if explicitly supplied/authorized, but it does not become a hidden dependency or justify a full-keyword-universe claim.

## 15. No silent deep competitor audit

Base MK03 does not include backlink audit, technical SEO audit, Core Web Vitals, schema audit, traffic/revenue estimates, advertising analysis, conversion audit or full competitor content inventory.

Inspect only what is needed to support competitor-derived demand/gap decisions.

## 16. Gap states stay explicit

Every material candidate ends in an explicit state equivalent to:

```text
CONFIRMED_GAP
ALREADY_COVERED
REJECT_OFF_SCOPE
HOLD_EVIDENCE
```

No silent drops are allowed.

## 17. Gap != automatic new page

```text
CONFIRMED SEMANTIC GAP != CREATE PAGE
COMPETITOR HAS PAGE != CLIENT NEEDS SAME PAGE
```

MK03 may state a bounded page/topic/section opportunity when supported, but full page ownership, target architecture and implementation-ready TZ belong to other products.

## 18. Current client-site coverage must be current enough for the claim

Historical inventories and old reports are not proof of current coverage. When the gap decision depends on whether the client already covers a topic, inspect/reconcile current public evidence or preserve uncertainty.

```text
OLD ABSENCE != CURRENT SITE ABSENCE
SEARCH ABSENCE != SITE ABSENCE
```

## 19. Evidence types remain separate

Distinguish at minimum:

```text
OBSERVED CURRENT SEARCH FACT
PUBLIC PAGE FACT
WORDSTAT DEMAND FACT
NORMALIZATION / ROUTING ASSIGNMENT
ANALYTICAL CONCLUSION
STRUCTURAL OPPORTUNITY RECOMMENDATION
BUSINESS FACT
UNKNOWN / HOLD
```

A conclusion may not masquerade as a provider fact.

## 20. Level-1 method != Level-2 case facts

No OKNO_MSK domain, query, URL, count, competitor, provider receipt or case-specific decision becomes a universal MK03 rule.

Promote only reusable failure classes and controls.

## 21. Client-facing usefulness is mandatory

A client deliverable must expose inspectable competitor/gap results, not only counts.

The recipient must be able to trace:

```text
SEARCH FAMILY
→ COMPETITOR
→ EVIDENCE-BEARING PAGE
→ NEW TOPIC/SEED
→ WORDSTAT / SEARCH EVIDENCE AS APPLICABLE
→ CLIENT COVERAGE DECISION
→ GAP STATE
→ NEXT OPPORTUNITY / HOLD REASON
```

## 22. Internal process language stays internal

Ordinary client material does not expose repository filenames, Step/Stage IDs, raw QA codes, commit hashes or internal state-machine prose unless specifically useful to the recipient.

## 23. Physical artifact QA is separate from analytical QA

A correct dataset is not automatically a usable client package. Final XLSX/PDF must be inspected at the layer where defects can exist, including final-byte rendering for PDF and visible-client-cell/package checks for XLSX when those formats are delivered.

## 24. Source/generator before rendered artifact

When a client artifact defect is found, fix the canonical source/generator/method first, regenerate and rerun QA. Hand-patching a final PDF or spreadsheet is not method closure.

## 25. Persistence discipline

Every material completed block follows:

```text
SAVE
→ QA
→ COMMIT/PUBLISH
→ REMOTE READBACK
```

Do not leave substantial productization or rehearsal progress only in conversation/local scratch state.
