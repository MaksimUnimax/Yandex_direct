# MK01 — AUTONOMOUS EXECUTION ROADMAP

Status: **VALIDATED ON OKNO_MSK / XLSX + PDF CLIENT PACKAGE DEFINED**

This is the operational sequence for a real MK01 order. It is intentionally smaller than full KW-001 and has no hidden dependency on omitted stages.

## PRECONDITION

Client input must pass `CLIENT_INPUT_CONTRACT.md`: public site + primary region + included scope + exclusions + business/conversion job. No Google or mandatory private Yandex access is required.

## STEP 00 — Freeze order
Persist exactly what was purchased before demand evidence is seen.

## STEP 01 — Build current site/business profile
Establish what the public business actually offers and the domain vocabulary needed for relevance/clustering.

## STEP 02 — Build Wordstat acquisition manifest
Design bounded probes that expose demand vocabulary without pre-approving keywords.

## STEP 03 — Acquire and durably preserve Wordstat evidence
For each authorized item: request -> useful result -> persist occurrence/provenance -> readback -> accounting QA -> continue.

## STEP 04 — First triage
Remove obvious out-of-scope/noise families while preserving ambiguity. Triage is not full cleanup.

## STEP 05 — Conditional targeted second acquisition
Run only for a named unresolved gap that persisted evidence cannot answer. If no gap: `NOT REQUIRED / NO PROVIDER CALL`.

## STEP 06 — Full row-level cleanup
Every governed phrase receives explicit state + reason + evidence basis + uncertainty. No default KEEP.

## STEP 07 — Freeze semantic universe and Search routes
Preserve active, Search-required, deferred and excluded states plus complete demand/provenance join. No page ownership/architecture.

## STEP 08 — Targeted ordinary Yandex Search
Probe only material Search-resolvable semantic boundaries. No bulk rank tracking.

## STEP 09 — Task-first clustering
Whole phrase + current domain profile + expected user result -> task signature -> cluster contract -> semantic QA. Technical assignment alone does not make an outside-task member active.

## STEP 10 — Client materialization and release QA
Generate from current authority rather than manually patching client files.

Mandatory client outputs:

```text
1. seven-sheet XLSX semantic core
2. 4–8 page client PDF report from CLIENT_REPORT_SPEC.md
3. short marketplace/chat handoff message attaching both files
```

PDF and XLSX must use the same accepted counts and current authority. The PDF includes real current-job group examples and does not invent downstream recommendations.

Run separately: DATA QA; SEMANTIC QA; WORKBOOK QA; PDF REPORT QA; RECIPIENT-LANGUAGE QA; VISUAL QA; OWNER/RECIPIENT TASK QA; PERSISTENCE/REMOTE READBACK QA.

## CLIENT HANDOFF

After Step 10 PASS, package according to `PRODUCT_PACKAGING.md` and fill `CLIENT_HANDOFF_TEMPLATE.md`. Internal audit sidecars do not replace client files and are not automatically sent.

## PRODUCT COMPLETION

Done only when scope recorded + Yandex evidence durable + full phrase accounting + uncertainty preserved + clustering semantic QA PASS + XLSX PASS + client PDF PASS + handoff packaged + remote identity/readback PASS.

Outside completion: page ownership, SEO architecture, competitor gap audit, implementation TZ, Alice/AEO, Google SEO.

## REVISION RULE

After order scope is recorded, material changes to region/site/business families are logged as revisions. Re-run only affected evidence/analysis where justified; do not erase or blindly recollect valid historical evidence.
