# MK01 — GENERAL RULES

Status: **ACTIVE / UNIVERSAL FOR MK01 / EXTRACTED FROM OWNER-APPROVED KW-001 AUTHORITIES**

These are Rule Level A — cross-step rules for MK01. Step-specific rules live in `steps/*` and may add stricter controls. Concrete client/test values belong in Level 2.

## 1. Product identity

MK01 sells one result:

```text
SEMANTIC CORE FOR AN EXISTING PUBLIC SITE
= YANDEX DEMAND ACQUISITION
+ CONSERVATIVE CLEANING
+ EXPLICIT UNCERTAINTY
+ TARGETED ORDINARY YANDEX SEARCH WHERE A SEMANTIC BOUNDARY REQUIRES IT
+ TASK/INTENT CLUSTERING
+ RECIPIENT-READY SEMANTIC CORE
```

It does not silently include page ownership, architecture, competitor gap analysis, AI/Alice analysis or implementation TZ.

## 2. Yandex-only

All evidence and claims are scoped to Yandex. Google Ads, Keyword Planner, Google Search, Search Console, Trends and Google-derived frequency are outside MK01.

A Google-origin keyword supplied by a client is only an unverified candidate until validated by the Yandex workflow.

## 3. Existing-site mode only

Current validated base mode requires an existing readable public website. Do not silently treat a greenfield/no-site project as MK01.

## 4. Scope freeze before acquisition

Freeze at minimum: site, primary region, included business directions, explicit exclusions, business/conversion job, package identity and unresolved client questions. Evidence may change conclusions; it may not silently rewrite the purchased task.

## 5. Business truth before keyword volume

`SEARCH DEMAND != BUSINESS OFFER`; `WORDSTAT COUNT != BUSINESS FIT`; `PUBLIC BUSINESS RELEVANCE != INTERNAL BUSINESS PRIORITY`. Unknown private priorities remain unknown.

## 6. Current-site evidence has a timestamp

`DISCOVERY SUCCESS != DISCOVERY COMPLETENESS`; `OLD INVENTORY != CURRENT SITE TRUTH`. If later current-site evidence materially changes a semantic decision, affected consumers are rebuilt.

## 7. Evidence classes stay distinct

Keep separate client business facts, public-site facts, provider observations, analyst assignments/conclusions, recommendations and UNKNOWN/HOLD. Do not convert inference into observation.

## 8. Seeds are acquisition probes

`SEED != FINAL KEYWORD`; `SITE CATEGORY != AUTOMATIC FINAL TAXONOMY`. Every probe needs an information purpose.

## 9. Provider acquisition is a data contract

Provider success is not completion until useful evidence is durably saved and read back. Preserve material occurrence/provenance fields including phrase, count, row role, seed/request, region, device/operator mode when applicable, acquisition time, source/request identity, raw/durable evidence and completeness/truncation state when available.

## 10. Persist before continuing paid/provider work

`USEFUL PROVIDER RESULT -> SAVE -> READBACK + ACCOUNTING QA -> NEXT MATERIAL PROVIDER ACTION`. Chat/runtime is transport, not durable evidence storage.

## 11. Cost never downgrades evidence

Avoid redundant requests, but do not choose weaker evidence merely to protect a provisional cheap package. Every material request needs a credible information-gain reason.

## 12. Preserve the full acquired universe

Do not persist only accepted/high-frequency phrases. Keep active, excluded, uncertain/deferred, low-frequency, association/similar rows and raw duplicate occurrences. Deduplication is a separate normalized layer.

## 13. Triage is not cleanup

`FAMILY DECISION != MEMBER-ROW ACCOUNTING`. Early family screening cannot be presented as row-level completion.

## 14. Frequency is not relevance

`LOW FREQUENCY != IRRELEVANT`; `HIGH FREQUENCY != RELEVANT`; association/volume does not prove semantic fit. KEEP requires positive evidence.

## 15. Uncertainty is valid

REVIEW, SEARCH_REQUIRED, DEFERRED, HOLD and equivalent states are legitimate. Do not simplify the core by silently deleting uncertainty.

## 16. Step5 acquisition is conditional

Second acquisition runs only for a named gap not answered by persisted evidence and remains union-compatible with the first acquisition.

## 17. Step5A is excluded from base MK01

Competitor-derived acquisition belongs to MK03 or a future explicitly priced add-on.

## 18. Search is targeted evidence

Ordinary Yandex Search is used only where an unresolved semantic/intent boundary materially needs it. `EXACT QUERY OBSERVATION != UNPROBED QUERY EVIDENCE`; normalized projection is not raw provider evidence.

## 19. Clustering is task-first

Read the complete phrase, apply current domain profile, identify expected user result, derive task signature, match the current cluster contract, then verify. Lexical similarity alone does not define a cluster.

## 20. Cluster count is not invented

If no explicit count/range is required, count emerges from supported task boundaries. Any external count constraint must be recorded separately with its trade-off.

## 21. No page-architecture leakage

MK01 may use task/intent compatibility for clustering, but does not issue final page-owner, create/split/merge, cannibalization or architecture decisions.

## 22. Corrections are atomic

If an assignment changes, rebuild all fields and summaries derived from that contract. `CORRECTED ID != CORRECTED ROW`.

## 23. Fix defect classes, not examples

`ROOT CAUSE -> FAILURE CLASS -> METHOD/GENERATOR FIX -> IMPACT SET -> REGRESSION`. One-row patch is not closure when the cause can repeat.

## 24. Client artifact is a view of current authority

Do not hand-maintain competing workbook truth. Generate recipient files from current accepted semantic/demand/provenance authorities.

## 25. Standalone workbook must be usable

The semantic core is a real recipient-ready XLSX/equivalent, not instructions to join internal TSVs. Preserve distinct views for full universe, active core, cluster summary, unresolved/review work and methodology/provenance.

## 26. Russian display layer

Visible sheet names, headers, statuses, metric descriptions and explanations use clear Russian professional language. Technical IDs/API codes are secondary traceability only.

## 27. Wordstat metric semantics are explicit

A number attached to a phrase is not automatically exact frequency. Explain report type, region, device/operator mode, operator semantics, snapshot and aggregation where applicable. Broad/no-operator count is not exact phrase frequency or traffic forecast.

## 28. QA layers are separate

`COUNTS RECONCILE != SEMANTIC CORRECTNESS`; `FILE OPENS != WORKBOOK USABILITY`; `AUTOMATED QA PASS != OWNER/RECIPIENT ACCEPTANCE`.

## 29. Private Yandex access is optional

Base MK01 must execute without mandatory Webmaster/Metrika/Direct access. Never request client passwords.

## 30. Durable completion

A material block is complete only after `SAVE -> COMMIT -> REMOTE READBACK -> COUNT/HASH/IDENTITY CHECK WHERE APPLICABLE`.

## 31. Authority precedence

Detailed source KW-001 methods override this summary when stricter. Executable MK01 = universal rules + current client profile + current constraints + current evidence.
