# MK02 — GENERAL / CROSS-STEP RULES

Status: **ACTIVE PHASE-3 EXTRACTION / RULE LEVEL A**

These rules govern the whole MK02 product. Per-step rules may strengthen them but may not weaken them.

## 1. Product and evidence boundary

```text
MK02 = YANDEX SEMANTIC CORE
     + PAGE OWNERSHIP
     + SEARCH-ONLY TARGET ARCHITECTURE
     + EVIDENCE-SUPPORTED IMPLEMENTATION SPECIFICATIONS
```

Google and AI/Alice/Neuro are outside base scope.

Step5A competitor semantic expansion is outside base scope and belongs to MK03.

A dedicated standalone query→page/cannibalization audit remains MK04; MK02 uses competing-page diagnosis only to the depth needed to prevent wrong architecture actions.

## 2. Level separation

```text
LEVEL 1 = reusable MK02 method
LEVEL 2 = current client/test facts
```

No OKNO_MSK URL, phrase, action, count or business fact becomes a universal MK02 rule.

## 3. Scope before acquisition

Freeze before provider work:

- exact public site;
- primary region;
- business/conversion job;
- included directions;
- exclusions;
- known site-change constraints/protected elements;
- purchased commercial capacity once Phase 8 defines it.

Evidence discovered later does not silently rewrite the sold task.

## 4. Current site is evidence, not timeless truth

A historical inventory or one read pass is not proof of current completeness.

When ownership/architecture depends on current existence/content/topology, refresh or independently reconcile current site evidence according to the current-site gate.

```text
OLD INVENTORY ABSENCE != CURRENT PAGE ABSENCE
KNOWN URL LIST != CURRENT SITE UNIVERSE
```

## 5. Provider calls require information gain

Wordstat/Search/private Yandex calls are not made merely because tools are available.

Before a new call:

```text
NAMED DECISION GAP
+ WHY SAVED EVIDENCE IS INSUFFICIENT
+ HOW RESULT CAN CHANGE DECISION
+ COST/QUOTA/ACCESS STATE
```

Useful acquisition is persisted/read back before the next material acquisition interaction.

## 6. Semantic foundation inherits MK01 controls

MK02 semantic acquisition/cleaning/clustering retains all applicable accepted MK01 protections, including:

```text
SEED != FINAL KEYWORD
LOW FREQUENCY != IRRELEVANT
HIGH FREQUENCY != RELEVANT
NO REJECTION RULE MATCHED != KEEP
ASSOCIATION/VOLUME != BUSINESS FIT
EXACT SEARCH OBSERVATION != UNPROBED FAMILY EVIDENCE
CLUSTERING = USER TASK / EXPECTED RESULT FIRST
UNCERTAINTY MUST REMAIN EXPLICIT
```

The current accepted semantic product state is the activation authority for every downstream MK02 layer. Historical ownership/action files may enrich accepted active phrases, but their legacy technical flags (`ASSIGNED`, old working markers or equivalent) may not reactivate a phrase that the current semantic authority classifies as review, excluded or outside the active core.

```text
CURRENT ACCEPTED SEMANTIC PRODUCT STATE
>
LEGACY DOWNSTREAM ASSIGNMENT / ACTIVATION FLAG
```

Before ownership, reconcile the exact active phrase set from the current semantic authority; use older downstream rows only as joined evidence for that set.

## 7. Page ownership is a separate decision layer

Ownership answers where the user task should primarily be served on the **current** site.

Mandatory distinctions:

```text
EXACT PHRASE OWNER
!= FAMILY / STRUCTURAL-UNIT OWNER
!= SUPPORTING PAGE
```

and:

```text
TARGET / INTENDED OWNER
!= SEARCH-ENGINE OBSERVED RELEVANT URL
```

A cluster-level owner table never substitutes for complete phrase→page accounting.

## 8. Full-member coherence before ownership

Do not assign an owner from a label or representative phrase alone.

Broad/weak/mixed clusters require member-level falsification. Materially different terminal tasks are split, corrected or left unresolved.

```text
REPRESENTATIVE QUERY != WHOLE CLUSTER PROOF
LEXICAL URL/TITLE MATCH != PAGE OWNERSHIP
```

## 9. Search absence is not site absence

```text
TARGET PAGE NOT SEEN IN SEARCH
!=
PAGE DOES NOT EXIST ON SITE
```

Search and current-site discovery are separate evidence routes.

## 10. No suitable current owner is not a CREATE decision

```text
NO_SUITABLE_EXISTING_PAGE != CREATE
```

CREATE belongs to structural alternative analysis and requires current-site/content reuse checks plus demand/Search/business evidence appropriate to the decision.

## 11. Structural action cannot prove itself

Every material action must be caused by independent evidence.

```text
ACTION LABEL != DIAGNOSIS
ACTION DESCRIPTION != EVIDENCE
PHRASE COUNT != NEW PAGE VALUE
```

Separate:

- structural gap;
- content enhancement gap;
- final action.

## 12. Current owner correctness does not mean optimization is complete

```text
KEEP STRUCTURAL OWNER
!=
PAGE PERFORMANCE / CONTENT / SEO QUALITY PASS
```

MK02 is not a full technical/on-page audit.

## 13. Current content reuse before CREATE

No exact owner does not automatically mean no current coverage.

Before informational/new-page CREATE, inspect plausible existing hubs/articles/services/children where the task may already be sufficiently covered or can be expanded.

## 14. Business truth != client strategic goal

A company may truthfully discuss a topic without wanting a standalone acquisition path for it.

Preserve the evidence source of owner/business goal:

```text
CLIENT-STATED
PUBLIC-SITE EXPLICIT
PUBLIC-SITE INFERRED
ANALYTICS/SALES EVIDENCE
UNKNOWN
```

Unknown material policy blocks strong strategic claims.

## 15. Structural corrections propagate atomically

If a material unit/task/owner changes:

```text
CORRECTION
→ REBUILD ENTITY-DERIVED METADATA
→ REBUILD OWNERSHIP / ACTION / LINK / PAIR OUTPUTS
→ REBUILD DECLARED CLIENT VIEWS
→ INDEPENDENT TARGET-CONTRACT QA
```

```text
NEW CANONICAL UNIT + OLD UNIT METADATA = FAIL
```

Known regression cases reaching zero do not prove global correctness; global coherence review must remain capable of finding new defects.

## 16. Competing pages are not automatically cannibalization

```text
RELATED PAGES != CANNIBALIZATION
CURRENT MULTI-URL / SERP OVERLAP != HISTORICAL COMPETITION
HISTORICAL COMPETITION != PROVEN HARM
```

Base-public mode can produce bounded current warnings/relationship diagnoses. It cannot upgrade one current Search snapshot into historical/harm claims.

## 17. Private Yandex history is mode-controlled

Before any historical competing-page claim, declare mode:

```text
BASE_PUBLIC_EVIDENCE_MODE
ENHANCED_WITH_ACCESS_MODE
RESEARCH_GRADE_HISTORY_REQUIRED_MODE
```

If client-private history is optional in base mode and unavailable, the base product may still pass with bounded claims.

If history is required by the promised claim and unavailable, that stronger part is blocked/degraded.

## 18. Target architecture != current as-is topology

Maintain two distinct layers:

```text
TARGET SEARCH ARCHITECTURE
CURRENT PUBLIC SITE TOPOLOGY
```

The target layer says what should own/support/connect tasks. The as-is layer says what pages and literal links actually exist now.

Never report a recommended edge as already implemented without literal current link evidence.

## 19. A closed known-URL list cannot prove completeness

Because current topology is material to MK02, the accepted upstream URL list cannot prove its own completeness.

Use independent current-site discovery/reconciliation sufficient for the claim.

Sitemap may supplement discovery but does not prove HTML reachability.

## 20. Tool selection follows fact-to-observe

Do not automatically build custom crawler/code.

```text
FACT TO OBSERVE
→ CURRENT AVAILABLE NATIVE TOOL
→ COVERAGE/REPEATABILITY/TERMINATION QUALIFICATION
→ CUSTOM CODE ONLY FOR NAMED GAP
```

Runner/source reachability and full-run reliability are separate states.

## 21. Semantic mapping != physical site change

A phrase/task may be correctly assigned to an existing page without requiring any website edit.

Every downstream action distinguishes:

```text
ANALYTICAL MAPPING
REAL SITE CHANGE REQUIRED = YES | NO | UNRESOLVED
```

`NO_SITE_CHANGE` is a valid positive implementation result.

## 22. Correct action != implementation-ready ticket

READY requires resolved implementation detail, not just a good idea.

Where applicable:

```text
PAGE/OBJECT
WHY
AS-IS
EVIDENCE MEANING
EVIDENCE LOCATOR
IMPLEMENTATION MODE
EXACT CHANGE
EXACT LOCATION/CONTEXT
TO-BE
DEPENDENCIES
PRESERVATION REQUIREMENTS
ACCEPTANCE CHECK
```

Missing material placement/context/business detail means clarification/pending, not READY.

## 23. Evidence meaning != evidence locator

A filename/ID/row locator is audit provenance, not a client explanation.

Implementation-ready client material needs both:

```text
EVIDENCE_MEANING
EVIDENCE_LOCATOR
```

The locator may stay secondary/internal; ordinary client prose explains the observed reason.

## 24. Company-specific facts require company-specific evidence

Do not invent inclusions, exclusions, warranty, exact service process, material choices, price/service boundaries or other business facts to make a recommendation look complete.

If a business fact is necessary:

```text
CONCRETE QUESTION
→ PENDING BUSINESS DETAIL
→ WHAT BECOMES READY AFTER ANSWER
```

## 25. Implementation specification != production schedule

```text
IMPLEMENTATION-SPEC READY
!= IMPLEMENTATION-SCHEDULE READY
```

Do not invent owner, effort, capacity, timing, internal business importance or measurement baseline.

Analytical priority may be provided with clear limitations. A real NOW/NEXT/LATER schedule requires real implementation calibration.

## 26. Accounting batch != work package

A batch may prove no actions were lost. It is not automatically implementable as one task.

Decompose to manageable work packages when independent implementation/acceptance is required, preserving exact source membership.

## 27. Dependencies must remain explicit

A lower-impact prerequisite may need to precede a higher-impact downstream action. Dependency logic is separate from estimated importance.

Never hide dependency cycles or impossible sequencing under a score.

## 28. Recheck trigger != success metric

Uncertainty governance answers when to reconsider a decision. Implementation measurement answers whether a completed change achieved the intended observable state/outcome.

At minimum every READY change has an implementation acceptance check. Performance metrics are only used when the source/baseline exists and is in scope.

## 29. Report materialization is not new research

Once research is complete, missing report detail does not authorize silent new site/Search/Wordstat/classification work merely to upgrade readiness.

```text
REPORT MATERIALIZATION != NEW PROJECT RESEARCH
```

If evidence is missing, move the item to a concrete clarification/check unless a separately authorized research task is opened.

## 30. Implementation report is action-first

The implementation report answers:

```text
WHAT TO DO
WHY
WHERE
HOW
WHAT TO CLARIFY
HOW TO CHECK RESULT
```

It is not a second research log and not a profession-branded “SEO specialist guide”.

## 31. Ready recommendations are unique and action-specific

Generic cloned steps are forbidden.

Each READY item must contain action-specific nouns, page/context and implementation operations. Obvious UI mechanics such as “open page / find block / click link” do not count as implementation steps.

## 32. Ambiguous placement cannot be READY

```text
"BEFORE X OR Y"
"IN ONE OF THESE BLOCKS"
"WHERE APPROPRIATE"
```

is not a ready placement when exact placement is material.

Move to clarification or perform the authorized evidence work before research closes.

## 33. Analysis cannot be left to the implementer

A supposedly ready instruction cannot say “classify these items”, “choose categories”, “decide which pages” if that analysis is part of the sold research.

Perform the mapping/classification during the research or mark it as pending.

## 34. Placeholders forbidden in READY client text

No TBD/TODO/[date]/future-value placeholder in ready examples or tasks.

## 35. Numbering is not a schedule

Document numbering exists for navigation/acceptance unless a real calibrated sequence exists.

Never imply “1 must be implemented before 2” merely because items are numbered.

## 36. Duplicate visible page/link decisions must be consolidated

Internal authority may contain multiple supporting rows. The client-visible result must not show duplicate source→target pairs without explaining genuinely different contexts.

## 37. Supporting tables need plain-language operating meaning

Before topic→page or page→page tables explain:

```text
WHAT THIS TABLE SHOWS
WHY THE CLIENT NEEDS IT
HOW TO USE IT
```

A bare register is not a client-ready instruction surface.

## 38. Client report is not a defensive prohibition list

Client space is for useful actions, clarification and explanation.

Preservation requirements are stated positively and locally inside the affected action/acceptance criteria.

```text
CLIENT REPORT = WHAT TO DO + WHY + HOW + RESULT
```

## 39. Internal process history stays internal

Do not expose action IDs, Stage/Step labels, repository filenames, QA IDs, failure-history narration, provider-call counts or quarantine/state-machine prose in ordinary client text.

## 40. Temporal facts stay attached to the correct object

```text
RANKING PERIOD != PUBLICATION DATE
OBSERVATION DATE != CONTENT UPDATE DATE
SNAPSHOT DATE != PAGE CREATION DATE
```

Do not transfer a date/period from one fact to another.

## 41. Client report must explain findings, not only steps/counts

MK02 inherits the MK01 owner correction:

```text
CLIENT REPORT != EXECUTION PROTOCOL
CORRECT COUNTS + CLEAN LAYOUT != RECIPIENT VALUE
```

The analytical layer explains material findings. The implementation layer explains actions. Neither is allowed to become a repository chronology.

## 42. Physical artifact QA is separate

File existence does not prove usability.

Where XLSX/DOCX/PDF are delivered, inspect actual sheets/pages and test the recipient task.

## 43. Source/generator before rendered artifact

When a client artifact defect is found, fix canonical source/generator/method first, regenerate, then re-run QA. Hand-patching only the final PDF is not closure.

## 44. Persistence discipline

Every significant completed block:

```text
SAVE
→ COMMIT/PUSH
→ REMOTE READBACK
```

Do not accumulate major productization progress only in conversation/local state.


## 45. Final-artifact QA is layered

Final client files require checks at the layer where a defect can exist.

For XLSX:

```text
VISIBLE CLIENT CELLS
+ WORKBOOK/SHEET STATE
+ RAW PACKAGE XML / TABLE METADATA
+ FORMULA-ERROR SCAN
```

For PDF:

```text
PARSE / TEXT EXTRACTION
+ CLIENT-LANGUAGE SCAN
+ FINAL-BYTE RENDER
+ PAGE-FLOW / ORPHAN-HEADING REVIEW
```

A clean parser/hash result cannot substitute for rendered page-flow review. A clean visible worksheet view cannot substitute for checking package metadata when internal terminology is forbidden. After any correction, inspect/revalidate the **post-correction final bytes**, not an earlier render. Source/generator correction remains the preferred closure path before a final binary replacement.

## 46. Target model precedes current-site reconciliation

MK02 is a target landing architecture product, not a current-site audit with a change appendix.

```text
ACCEPTED SEMANTICS / USER TASK / INTENT
→ COMPLETE PHRASE AND CLUSTER TARGET ROUTES
→ TARGET PAGE REGISTRY / HIERARCHY
→ FULL PAGE SPECIFICATIONS, INCLUDING KEEP
→ CURRENT-SITE RECONCILIATION
→ PHYSICAL CHANGE DELTA AS SUBSET
```

The current URL may confirm, reject or qualify an already defined target role. It may not silently create that role by being present. `KEEP` / no-change is a positive page-specification result and stays visible. `NO_STANDALONE` requires a named owner or parent route. An unresolved role keeps an explicit unresolved state and may not receive a fabricated URL.

Any upstream target-role correction invalidates all affected phrase routes, cluster routes, hierarchy, reconciliation, page specs, change delta and client artifacts until they are rebuilt and independently revalidated.

## 47. Market-grade mapping must keep demand, page role and boundary visible together

A technically complete mapping is not client-ready if the recipient must join separate sheets to answer basic page-planning questions.

The primary phrase→target-page view keeps the preserved demand indicator on the same row as the phrase, cluster and target page. The page-level view keeps the primary query and a compact set of strongest compatible secondary queries with their **individual** demand indicators.

```text
PHRASE + DEMAND + CLUSTER + TARGET PAGE = ONE DIRECT WORKING VIEW
PRIMARY QUERY + SECONDARY QUERIES + INDIVIDUAL DEMAND = PAGE-SPEC INPUT
WORDSTAT COUNTS ARE NOT SUMMED INTO INVENTED PAGE VOLUME
```

Every target page has one explicit primary page job. Secondary tasks are separated from topics that belong elsewhere. After normalization, the same material topic may not appear in both own coverage and elsewhere without a written sub-intent distinction.

```text
PRIMARY PAGE JOB = ONE CLEAR ROLE
OWN COVERAGE ∩ UNEXPLAINED ELSEWHERE = ∅
```

Recommended H1 is part of the target-page specification. CREATE/OPTIMIZE pages also receive a supported Title direction/draft or an explicit evidence blocker. Description is not silently added to base scope.

Analytical SEO priority may be shown with its evidence basis, but it is never presented as production order, business priority, effort, deadline or forecast.

## 48. Complete authority does not justify repetitive PDF expansion

All target pages remain present in the canonical page-spec register and in a complete client-visible register. This does **not** require one nearly identical full PDF page for every `KEEP / NO SITE CHANGE` role.

Preferred client PDF pattern:

```text
COMPLETE COMPACT REGISTER OF ALL TARGET PAGES
+
DETAILED CARDS FOR CREATE / OPTIMIZE / ROUTE / RECHECK
+
DETAILED KEEP ONLY WHEN MATERIAL BOUNDARY / DEPENDENCY / SPECIAL EXPLANATION EXISTS
```

The analytical PDF must show a scannable visual/indented target hierarchy, not only a wide hierarchy table, because the architecture itself is a sold result.

```text
KEEP MUST REMAIN VISIBLE != EVERY KEEP GETS A FULL PAGE
LONGER PDF != MORE CLIENT VALUE
HIERARCHY TABLE ALONE != FAST ARCHITECTURE COMPREHENSION
```

No fixed PDF page count is a quality target. Recipient usefulness and information density are the gate.
