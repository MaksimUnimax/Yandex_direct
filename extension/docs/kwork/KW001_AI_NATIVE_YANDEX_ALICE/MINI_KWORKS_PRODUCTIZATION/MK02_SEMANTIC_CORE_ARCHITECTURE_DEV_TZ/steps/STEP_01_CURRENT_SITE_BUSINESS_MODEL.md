# MK02 STEP 01 — CURRENT SITE / BUSINESS MODEL

## PURPOSE
Build the current public-site/business profile needed for semantic relevance, later page ownership and architecture comparison.

## WHY THIS STEP EXISTS
MK02 cannot map demand to pages or recommend site changes from a stale/partial inventory. Current-site evidence is required both for business fit and for candidate page discovery.

## INPUTS
Frozen order; current public website; known client constraints; prior reusable discovery tooling/method.

## REQUIRED EVIDENCE
Current readable pages sufficient to understand products/services, page roles, taxonomy and business boundaries. Discovery provenance and snapshot time must be recorded.

## METHOD
Read the current site using the strongest suitable approved discovery route. Build a scoped business/page vocabulary model. Preserve current URL, page role, title/H1 or equivalent purpose evidence and relevant parent/child/sibling context. Do not claim whole-site completeness from one route. Architecture-grade independent discovery is performed later in Step13 when full topology is material.

## OUTPUTS
Current scoped business/page model; initial current URL/page inventory; vocabulary and business-fit profile; freshness limitations.

## SOURCE KW-001 AUTHORITY
KW-001 Step1; `CURRENT_SITE_FRESHNESS_AND_EXISTENCE_GATE.md`; MK01 Step01; Step14 discovery lessons for later completeness distinction.

## KNOWN FAILURE CLASSES
S02 one pass = timeless completeness; M11-05 Search absence = site absence; M12-12 old inventory absence = current absence; E14-01 closed list proves itself complete.

## ROOT CAUSES
Discovery success and known-page reconciliation were mistaken for current-site completeness.

## NON-REPEAT CONTROLS
Timestamp snapshot; preserve discovery route; separate initial business-model discovery from later architecture-grade topology reconciliation; never infer page absence from Search absence.

## CLAIM BOUNDARIES
This step builds enough current context for semantic work. It does not yet prove the complete current internal-link graph or final architecture universe.

## UNKNOWN / BLOCKER BEHAVIOR
Unreadable site blocks base MK02. Ambiguous page purpose remains unresolved; do not force page-role labels.

## PASS GATE
Business/site profile covers frozen directions; page evidence is current enough for the stated claim; snapshot/provenance recorded; no unsupported whole-site completeness claim.

## CLIENT-FACING MEANING
«Сначала разбираемся, что сайт реально предлагает сейчас и какие типы страниц уже существуют, чтобы собирать запросы под бизнес, а не под абстрактную тему.»
