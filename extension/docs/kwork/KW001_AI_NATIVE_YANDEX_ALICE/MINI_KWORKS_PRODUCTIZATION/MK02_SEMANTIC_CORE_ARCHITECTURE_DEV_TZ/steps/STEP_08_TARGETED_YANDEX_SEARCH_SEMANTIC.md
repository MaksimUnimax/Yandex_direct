# MK02 STEP 08 — TARGETED ORDINARY YANDEX SEARCH FOR SEMANTIC BOUNDARIES

## PURPOSE
Use ordinary Yandex Search only where a material semantic/task boundary cannot be resolved safely from the current preserved evidence.

## WHY THIS STEP EXISTS
Search can resolve result type, task/object ambiguity and expected content pattern, but one exact observation is easily overgeneralized and normalized exports can be mistaken for raw evidence.

## INPUTS
Frozen Step07 semantic universe; named unresolved questions; region/surface configuration; saved Search evidence reusable for the exact question when current enough.

## REQUIRED EVIDENCE
Exact query; region/surface/time; observed result set sufficient for the declared question; raw/projection fidelity state; decision/use of observation.

## METHOD
Before a new Search request, state the exact information gap and how the answer can change the semantic decision. Reuse saved evidence when valid. Persist useful observations before further acquisition. Keep exact-query evidence attached to the exact query; family generalization requires explicit supported rationale. Distinguish raw provider/browser evidence from normalized projection.

## OUTPUTS
Exact Search observation ledger; bounded decisions; remaining unresolved semantic cases; persisted evidence/readback.

## SOURCE KW-001 AUTHORITY
KW-001 Step9 narrow non-repeat controls; MK01 Step08; persistence/cost gates.

## KNOWN FAILURE CLASSES
S14 exact observation generalized to family; S15 normalized projection called raw; M11-05 Search absence = site absence.

## ROOT CAUSES
Search evidence was treated as broader/more durable/more structurally authoritative than the actual observation supported.

## NON-REPEAT CONTROLS
Exact query/time/region attached; family generalization declared separately; Search absence never proves site absence; provider call needs information gain; useful evidence persisted immediately.

## CLAIM BOUNDARIES
This step resolves semantic boundaries only. It does not yet assign final page ownership or prove a new page is required.

## UNKNOWN / BLOCKER BEHAVIOR
If Search evidence is insufficient or provider use is not justified, keep the phrase unresolved/deferred. Do not force a semantic answer to make downstream tables complete.

## PASS GATE
Every used observation maps to a named question; exact scope preserved; raw/projection fidelity explicit; no unsupported family generalization; remaining ambiguity explicit; evidence persisted/read back.

## CLIENT-FACING MEANING
«Обычную выдачу Яндекса проверяем точечно только там, где она действительно помогает понять смысл запроса или ожидаемый тип результата.»
