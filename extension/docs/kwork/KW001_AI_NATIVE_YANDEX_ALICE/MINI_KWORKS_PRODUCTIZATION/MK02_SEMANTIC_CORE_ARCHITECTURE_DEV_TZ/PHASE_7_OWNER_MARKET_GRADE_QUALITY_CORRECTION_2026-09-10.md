## Confirmed product-quality defects

### QG-01 — Demand detached from the primary mapping view

The main phrase→target-page workbook view did not place the preserved Wordstat indicator directly beside phrase/cluster/target page, so a client had to join another sheet for a basic sort-by-demand task.

Correct rule:

```text
PHRASE + INDIVIDUAL DEMAND + CLUSTER + TARGET PAGE
= ONE DIRECT WORKING VIEW
```

No invented sum of Wordstat values at page level.

### QG-02 — Page cards exposed only one representative query

A page-level spec should make keyword targeting legible without dumping thousands of phrases.

Required:

```text
PRIMARY QUERY + INDIVIDUAL WORDSTAT
TOP SECONDARY QUERIES + INDIVIDUAL WORDSTAT EACH
TOTAL ROUTED PHRASE COUNT
```

Normally 5–10 distinct useful secondary phrases where available.

### QG-03 — Page-role boundary could mix heterogeneous terminal tasks

Some client-visible page specs inherited broad unions of commercial, accessories, DIY, reviews, service and informational tasks into one “main task / intent” field. Some related topics could also appear in both page coverage and elsewhere/boundary fields.

Correct contract:

```text
ONE PRIMARY PAGE JOB
+ COMPATIBLE SECONDARY SUPPORT
+ SEPARATE SUPPORT/LINK TOPICS
+ SEPARATE ELSEWHERE/NAMED-OWNER TOPICS
```

After normalization:

```text
UNEXPLAINED OWN-COVERAGE ∩ ELSEWHERE = ∅
```

### QG-04 — H1 / Title target state insufficiently materialized

Every material target page should expose the recommended H1.

For CREATE / OPTIMIZE pages, Title direction/draft is required where existing evidence is sufficient. Do not invent metadata merely for template symmetry. Description remains outside automatic base scope.

### QG-05 — Analytical SEO priority insufficiently visible

A client should be able to see analytical importance without mistaking it for implementation schedule.

Allowed basis includes demand strength/breadth, target-architecture centrality, existence of a real current→target gap, dependency role and evidence confidence.

Forbidden inference:

```text
ANALYTICAL SEO PRIORITY = IMPLEMENTATION ORDER / EFFORT / BUSINESS VALUE / UPLIFT
```

### QG-06 — Analytical PDF hierarchy too table-heavy

Because target architecture is a sold result, the analytical PDF must include a directly scannable tree/indented hierarchy/branch view, not only a wide hierarchical table.

The table may remain as a detailed companion.

### QG-07 — 60 complete page specs were mechanically expanded into a 71-page PDF

Completeness was overcorrected into repetition: 48 KEEP roles remained valuable, but many did not justify a separate nearly identical full PDF page.

Correct PDF pattern:

```text
COMPLETE COMPACT REGISTER OF ALL TARGET PAGES
+
DETAILED CARDS FOR CREATE / OPTIMIZE / ROUTE / RECHECK
+
DETAILED KEEP CARD ONLY WHEN MATERIAL SPECIAL BOUNDARY / DEPENDENCY EXISTS
```

Permanent rule:

```text
KEEP REMAINS VISIBLE != EVERY KEEP GETS A FULL PDF PAGE
```

### QG-08 — OKNO_MSK is not a complete portfolio demonstration of CREATE

OKNO_MSK honestly produces zero CREATE actions after target-first reconciliation. This is valid client evidence but a weak sole portfolio example for the commercial product.

Do **not** falsify OKNO_MSK.

Phase 10 portfolio work must, if a CREATE workflow needs to be demonstrated, use a separate truthful validated case or clearly labelled synthetic/demo structure that does not masquerade as a real client finding.
