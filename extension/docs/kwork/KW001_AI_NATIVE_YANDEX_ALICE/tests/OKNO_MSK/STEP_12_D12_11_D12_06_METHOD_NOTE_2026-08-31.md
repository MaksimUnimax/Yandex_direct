# Step 12 — D12-11 + D12-06 correction method note

Date: 2026-08-31
Status: execution method persisted before workflow run
Step boundary: Step 12 only. No cannibalization/conflict verdict is allowed here.

## Why D12-11 cannot be safely closed before D12-06 data exists

D12-11 requires every structural recommendation with a material unresolved downstream conflict dependency to look provisional/deferred rather than implementation-ready `FINAL/HIGH`.

The historical first pass contains `step13_followup_required=true`, but D12-06 explicitly records that those flags were manually selected and therefore cannot define the complete dependency universe. Reusing only that boolean would repeat the defect.

Therefore the corrected order inside this execution block is:

```text
FINAL CORRECTED ROUTING INPUTS
→ DETERMINISTIC PAGE-PAIR UNIVERSE
→ DERIVE WHICH PAIRS NEED LATER DIRECT SEARCH CHECK
→ MAP THOSE PAIRS BACK TO STRUCTURAL UNITS
→ CORRECT RECOMMENDATION MATURITY / CONFIDENCE
→ INDEPENDENT RECOMPUTATION
→ GITHUB PERSISTENCE + READBACK
```

The old manual flags are retained only as a conservative known-signal input for `later_direct_search_check_needed`; they do not create pair rows and therefore do not define the pair universe.

## Deterministic pair-universe sources

A pair is materialized when at least one of these relationships exists in persisted final Step-12 routing data:

1. one corrected structural unit explicitly has a distinct primary and supporting page;
2. one original effective semantic cluster is now distributed across two or more distinct primary page destinations after the V5 phrase-level correction;
3. the accepted D12-07 new-page hierarchy plan explicitly connects a proposed page to an existing inbound/outbound page.

Pairs are deduplicated by normalized URL pair. Proposed `PROPOSED_NEW:/...` destinations are normalized to `https://okno-msk.ru/...` for graph comparison while their proposed-page nature remains visible in the source artifacts.

## When Step 12 requests a later direct Search check

`later_direct_search_check_needed=true` is derived conservatively if one or more of these persisted conditions applies:

- a contributing structural unit already has `MATERIAL_BOUNDARY_GAP`;
- a contributing structural unit is already Search-provisional;
- an accepted proposed-page hierarchy still has a material unresolved Search boundary;
- the same upstream semantic source routes to non-hierarchical multiple primary destinations;
- a historical manual follow-up flag exists for a contributing source cluster. This last condition preserves known risk but never creates the pair universe.

The pair file also records why the relation may be perfectly normal (parent/child, primary/supporting, planned internal-link journey, or distinct user-task split). Step 12 does not decide whether overlap is harmful.

## D12-11 maturity rule

The corrected V2 actions use only these canonical maturity states:

```text
FINAL_WITHIN_STEP12_EVIDENCE
PROVISIONAL_PENDING_STEP13_CONFLICT_CHECK
DEFERRED_PENDING_MISSING_EVIDENCE
```

Rules:

- a row already deferred for missing evidence stays deferred;
- a row participating in a material later-search pair becomes `PROVISIONAL_PENDING_STEP13_CONFLICT_CHECK` unless already deferred;
- an older non-Step13 provisional row with unresolved material evidence becomes `DEFERRED_PENDING_MISSING_EVIDENCE`;
- everything else is `FINAL_WITHIN_STEP12_EVIDENCE`.

A Step13-dependent row cannot remain `HIGH`. Existing evidence-derived confidence is otherwise preserved.

The accepted D12-07 hierarchy plan is also materialized into V2 `hierarchy_clarity`, so final actions no longer say hierarchy is pending after the hierarchy artifact was already accepted.

## Independent verification

The verifier does not import the generator. It independently recomputes the expected URL-pair key set from the three source relationships above, recalculates material direct-search triggers, reconstructs expected dependency units, and fails on:

- missing/extra/duplicate pair rows;
- search-check flag mismatches;
- missing/extra dependency units;
- any dependency row that remains `FINAL` or `HIGH`;
- noncanonical maturity values;
- D12-07 candidate pages whose hierarchy is not materialized into V2;
- any historical known follow-up cluster that has no graph-derived pair at all;
- any Step-13 harm/conflict verdict field or confirmed-harm cell.

Only after this verifier passes may D12-11/D12-06 be considered candidates for manual closure/readback. D12-05 remains a separate final independent-QA defect and is not closed by this workflow.
