## F-017 exact SOP — sellable now

**Marketplace:** Kwork  
**Listing id:** `797906`  
**Seller:** `Veronika_VM`  
**Title:** `Семантическое ядро до 500 сгруппированных ключевых фраз`  
**Verdict:** `YES — READY NOW`

Market evidence:

```text
price = 3,000 ₽
volume = up to 500 grouped keyphrases
normalized displayed scope ≈ 600 ₽ / 100 keys
advertised deadline = 10 days
seller-displayed usual completion = 2 days
seller = 5.0 / 798 completed orders
reviews shown = 13 positive / 0 negative
```

Client inputs:

```text
- website URL;
- target region;
- 10–15 pages/categories that need semantics;
- if pages do not exist: names/descriptions of future pages and offered products/services;
- competitor link for each page/category is requested as useful context;
- other business exclusions/constraints should be confirmed at intake.
```

Advertised client outcome:

```text
- up to 500 ВЧ/СЧ/НЧ phrases;
- Yandex Wordstat / Key Collector used by seller as working tools;
- manual cleaning of garbage, duplicates and non-target phrases;
- manual grouping for 10–15 site pages/categories;
- final understandable Excel workbook.
```

`Key Collector` is not a required client-facing data source. The actual promised data can be reproduced with the current accepted Wordstat path plus site/competitor reasoning.

Current execution:

```text
1. Receive URL, region and 10–15 target pages/categories.
2. Inspect each page/category offer and optional competitor page.
3. Build per-page seed map: head terms, synonyms, product/service modifiers, commercial intent, informational support terms where appropriate.
4. Run bounded regional Wordstat getTop collection for the strongest seeds.
5. Persist provider result after each explicit request.
6. Merge candidates while preserving source seed/page/category.
7. Normalize and remove exact duplicates, semantic duplicates, garbage, wrong geography and wrong intent.
8. Resolve cross-page cannibalization: one phrase should have one primary target page unless deliberately marked shared/review.
9. Assign each retained phrase to one of the 10–15 target pages/categories.
10. Classify ВЧ/СЧ/НЧ using a declared niche/region rule from observed frequency distribution.
11. Select up to 500 useful phrases; never pad an exhausted niche.
12. Produce XLSX with at minimum: target page/category, phrase, frequency, frequency band, optional source seed/competitor, review notes.
13. QA duplicates, page assignment, region consistency, relevance, row count and file readability.
```

Why `YES`:

```text
- no Google dependency;
- no Ahrefs/Keys.so requirement;
- no full-site crawler requirement;
- no one-SERP-request-per-key TOP clustering requirement;
- Wordstat can return up to 2,000 phrases per seed request;
- grouping to 10–15 pages is reasoning/artifact work already feasible now.
```

Direct approval does not block F-017.

# 6. WHAT THE MARKET SAMPLE ACTUALLY SAYS

## 6.1 Semantic-core work is the dominant opportunity

Most of the 17 cards are either semantic-core services directly or require the same reusable primitives. The repeated paid pattern is not "one magic SEO API". It is:

```text
acquire phrases
→ clean
→ dedupe
→ classify intent/frequency
→ group/assign
→ package into Excel
```

That pattern repeats at 100, 150, 160, 300, 500 and 10,000-key scopes and across ordinary SEO, competitor-derived research and Yandex Direct preparation.

## 6.2 The current Bridge already covers a commercially useful core

We do not need Direct approval to begin selling the semantic families above. Wordstat + Search + ordinary site analysis + artifact generation already cover multiple end-to-end client outcomes.

Direct is useful for later advertising-account analytics/workflows, but it is **not the bottleneck for the strongest demand cluster found in this sample**.

## 6.3 Our biggest weakness is orchestration, not another provider

For Wordstat-centric services, the provider exists. The missing product layer is the durable job around it.

For TOP clustering, Search exists. Again the missing product layer is the durable job around it.

This changes roadmap logic:

```text
wrong approach: keep adding providers before packaging existing primitives
better approach: productize repeated paid workflows first, then add providers that unlock multiple blocked families
```

## 6.4 Page/category mapping is now a first-class feature

F-017 gives direct market evidence that buyers pay not merely for a list of phrases but for a list **already distributed across concrete site pages/categories**.

That means a future `Semantic Core Builder` should not stop at:

```text
keyword + frequency
```

It should be able to produce:

```text
page/category
keyword
frequency
frequency class
intent
source/seed
confidence/review state
```

## 6.5 Cheap market prices imply automation and strict scope separation

Observed sellers frequently separate cheap base work from expensive add-ons:

```text
base general Wordstat frequency
vs exact frequency
base structural grouping
vs deep TOP clustering
base Yandex data
vs Google/external metrics
keyword collection
vs standalone cleanup
keyword collection
vs standalone TOP clustering
```

We should copy the **scope architecture**, not blindly copy the lowest price.

# 8. FINAL PRODUCT CONCLUSION AFTER F-017

The freelance sample gives a clear product direction:

```text
Yandex Marketing Bridge should first become a reliable SEO/semantic workbench,
not merely a collection of five provider buttons.
```

The highest-value next abstraction is a reusable **job/workflow layer** over the providers already implemented:

```text
JOB INPUT
→ controlled provider queue
→ checkpoint/resume
→ normalized evidence store
→ reasoning/transformation
→ QA/review states
→ client artifact
```

The first concrete job should be **Semantic Core Builder**, because it covers the largest share of observed paid demand and can already be executed with current provider primitives. It should include target-page assignment from day one because F-017 proves that this is a monetized client outcome, not an optional nice-to-have.

After that, the next strongest additions are:

```text
1. bulk SERP/TOP clustering job;
2. crawler/importer + technical SEO audit job;
3. Google organic SERP/competition provider;
4. external SEO-metric provider/importer.
```

This ordering is demand-driven by the 17 analyzed marketplace cards and deliberately avoids adding providers that do not unlock repeated paid workflows.
