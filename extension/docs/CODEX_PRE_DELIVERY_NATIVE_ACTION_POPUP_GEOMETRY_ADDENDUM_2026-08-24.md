# Codex pre-delivery addendum — native Chrome action-popup geometry

Date: 2026-08-24  
Status: **MANDATORY / PERMANENT BROWSER-SURFACE ADDENDUM**

This addendum is mandatory for every future installable Yandex Marketing Bridge candidate that exposes a Chrome action popup.

## Why this addendum exists

A complete Phase-2 controlled campaign passed while its popup harness opened `popup.html` inside a normal inactive extension tab. Owner-live then exposed an unusable/jumping native toolbar popup on the exact tested artifact.

A normal extension tab proves popup JavaScript transactions, but it does **not** prove the geometry/autosize behavior of Chrome's native action-popup host.

Therefore native toolbar popup geometry is a separate browser-owned assertion and cannot be substituted by:

```text
chrome.tabs.create({ url: chrome.runtime.getURL('popup.html') })
page.goto(chrome-extension://.../popup.html)
source/CSS inspection alone
unit tests alone
```

## Mandatory native venue

The browser gate must open the real action popup through the installed extension, for example:

```text
chrome.action.openPopup()
```

Then attach to the actual popup target/context and inspect the rendered native popup geometry.

For current qualified Chrome 151 coverage, the durable harness is:

```text
extension/tests/qa_browser/popup_chrome151_geometry_gate.mjs
```

Current harness source authority for the Phase-2 repair candidate:

```text
10bb3aca67295e5e515ff2ade8914b23e8458ca7
```

## Mandatory assertions

At minimum require:

1. the real installed extension's action popup opens successfully;
2. the target URL is the extension's real `popup.html`;
3. root viewport width remains within the product's governed width range;
4. root viewport height remains at/below Chrome's action-popup maximum and below any known affected autosize threshold selected by the product;
5. long content does not grow the root document beyond the governed popup viewport;
6. overflow is handled by an intentional internal scroller;
7. controls/settings below the fold remain present in the DOM and reachable through internal scrolling;
8. popup open/close/reopen does not mutate product state unexpectedly;
9. no real provider request is generated by geometry testing;
10. browser/harness checkout is clean after execution.

A PASS must include concrete measured geometry, not only visual prose.

## Relationship to B-01/B-02/B-03

Existing B-01/B-02/B-03 remain mandatory:

```text

B-02 Manual-ON transaction

```

The new native action-popup assertion is **B-04**. B-04 does not replace B-01/B-02/B-03 and they do not replace B-04.

The older Stage-4 harness may continue using an extension-tab popup venue internally for transaction execution if that remains a stable automation venue, but every final candidate must additionally pass B-04 through the real Chrome action-popup host.

## Failure classification

```text
exact candidate valid + native action popup opens + product geometry assertion fails
→ FAIL_PRODUCT

native action-popup venue cannot be created/attached due harness/environment failure before product assertion
→ FAIL_HARNESS

candidate/transport identity mismatch
→ FAIL_ARTIFACT
```

Do not weaken B-04 into source review after a browser failure.

## Permanent gate-authoring rule

When a browser surface is hosted by special browser chrome/UI — action popup, side panel, permissions UI, extension management surface, etc. — the final gate must exercise the real browser-hosted surface when its hosting behavior can affect product usability. Testing the same HTML in an ordinary tab is not equivalent.
