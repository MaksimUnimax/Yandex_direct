## 2. Что действительно реализовано

### B4A — строгая проверка перед существующим XML-нормализатором

Новый `candidate/shared/search_async_normalizer.js` проверяет исходную Base64-строку, UTF-8, размер и структуру XML до вызова неизменённого нормализатора 0.1.4. Ошибка провайдера, отсутствующий response и обрыв документа не становятся успешной пустой выдачей. Документированный код XML 15 распознаётся отдельно как отсутствие результатов. Отсутствующие необязательные поля остаются null; строки без URL не удаляются молча и получают отметку непригодности для URL-сравнения.

Это ограниченная проверка используемого XML-диалекта, НЕ универсальная реализация XML. DTD/пространства имён и неподдержанный синтаксис отклоняются с сохранением исходных данных у вызывающего B3. Старый mapper, его ранги/сниппеты/ограничения и обычный Search не переписаны. В B3 ошибка разбора пока сохраняется общим кодом ASYNC_NORMALIZATION_FAILED; более подробное состояние ошибки XML не заявляется реализованным.

### B4B — сохранённые разрешения и оценки расходов

Новый `candidate/shared/search_async_policy.js` использует настоящий существующий YMBPolicyModel и YMBCredentialRegistry. Он читает настройки Search, разрешённые методы и состояние credentials; другие сервисы и их настройки не меняет.

Разрешения хранятся отдельно по попыткам в IndexedDB. В одной транзакции записываются попытка, счётчики выбранного бюджета и время следующего разрешённого обращения. Несколько новых отложенных заданий используют общий бюджет в закреплённой области; скорость регулируется по каталогу отдельно для отправки и получения. При отказе по политике или бюджету разрешение не выдаётся. Получение уже заказанного результата не считается новым платным Search.

Повторное завершение одной попытки не начисляет/не возвращает расход второй раз. Доказанное отсутствие отправки возвращает предварительный резерв. Неизвестный исход POST сохраняет резерв и блокирует следующие отправки до разбирательства. Неизвестный GET при сохранённом состоянии не превращается в неизвестную платную отправку. Сбой сохранения оставляет блокировку вместо ложного успеха.

0,0305 рубля используется только как консервативная дневная оценка отложенного запроса, не как подтверждённый счёт. Документированные бесплатные HTTP-исходы учитываются отдельно; последующие ошибки самой асинхронной операции и фактическая сверка счёта требуют дальнейшего решения. Ключи и тела ответов в записях учёта не хранятся.

## 3. Важное незакрытое место общего учёта

**Старые синхронные Search/GenSearch пути ещё НЕ подключены к этой же атомарной процедуре разрешения.** Сейчас новый модуль объединяет новые отложенные задания и учитывает прочитанные счётчики старого run. Чтение старых счётчиков НЕ доказывает отсутствие гонки с одновременно работающим старым отправителем.

Поэтому полная задача общего admission/учёта ещё не принята. До интеграции и проверки общего разрешения для всех затронутых путей нельзя объявлять cross-mode concurrency безопасной. При следующем шаге это обязательная часть работы, а не отложенная необязательная оптимизация.
