## Что реализовано до обрыва и сохранено

`candidate/b8/search_async_export.js` и два точных delta добавляют `exportPage` в отдельный async-протокол и ручной worker. Выгружается последовательная страница до 25 записей с локальным пределом 16 MiB. Это ограниченная материализация страницы, не постоянная память независимо от файла. В файле сохраняются запрос, параметры, состояние, исходный ответ и нормализованные строки. Файл не объявляется полным заданием, если есть продолжение.

Каждая следующая страница обязана указать ту же revision. Изменение исходного задания останавливает выгрузку вместо смешения версий. Одна слишком большая запись не обрезается и не перескакивается. Выгрузка не делает provider calls, не нормализует повторно и не удаляет исследовательские данные.

Используется неизменённый Patch A artifact store, отдельные бинарные записи и уже существующие attachment descriptors. При неоднозначной ошибке записи outbox сначала читается состояние: уже переданный доставке файл не удаляется. Ответ в чат содержит небольшие счётчики, не raw payload. Одновременные async Manual-вызовы одного worker не перезаписывают друг друга.

## Исправления и identity boundary

В первоначальной новой выгрузке был пойман неверный расчёт размера завершающей части JSON на один байт. Сохранённый исходный набор после исправления имеет 84 PASS в `evidence/B8_ALL_SOURCE.tap`.

Также на фактическом B7 input воспроизведено: autoInstall формировал workerId с двоеточием, которое запрещал его собственный валидатор. B8 delta заменяет разделитель на дефис; отдельная assertion проверяет RED старого input и GREEN B8.

Старый B7 report hash не совпадает с фактически сохранённым worker blob. Это не исправлялось молча: см. `B8_IDENTITY_RECONCILIATION.md`. Для B8 использованы фактические сохранённые байты и новая регрессия, а не неподтверждённый старый PASS.
