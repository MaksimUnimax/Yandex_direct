# Yandex Marketing Bridge — проверяемый кандидат, не релиз

База: пользовательская версия **0.1.4**. Метаданные manifest/package/product сохраняют 0.1.4 до отдельного выпуска. Этот каталог содержит объединённые изменения файловой доставки и отложенного Search; его нельзя принимать за исходную неизменённую 0.1.4 или устанавливать по номеру версии.

**RELEASE_ALLOWED = NO.** Браузерная приёмка, настоящая IndexedDB и память Chrome на объединённой версии не подтверждены. Здесь описаны исходники, а не обещание готовой безопасной сборки.

## Существующие сервисы

Сохранены Wordstat, обычный Search, GenSearch, Вебмастер, Метрика и Директ. Прежние команды и режимы остаются отдельными. Ручной запуск привязан к подтверждённому диалогу и вкладке; текст команды не задаёт ключи или произвольный сетевой адрес. Наличие кода сервиса не заменяет действительные credentials и разрешения.

## Отложенный Search: текущая граница

Отдельный протокол: `SEARCH_ASYNC_BATCH_API_V1`. Только ручной режим, активный Search, привязанный диалог, незанятая доставка и отсутствие другой активной операции. Автоматическая фоновая отправка/проверка и deferred Autorun не реализованы.

В manifest этого кандидата **нет** разрешения `https://operation.api.cloud.yandex.net/*`. Поэтому отправка **и получение** отложенных результатов сейчас отклоняются до сетевого обращения. Разрешение не включается командой из чата. Добавление host permission и проверка допуска — отдельное изменение, а не инструкция включить его вручную.

Локальные действия доступны в исходниках при выполнении проверок привязки/настроек:

| Действие | Назначение | Ограничение |
|---|---|---|
| `start` | Сохранить список и параметры, не отправляя запросы | 1–1500 уникальных после trim запросов; explicit maxRequests/maxCostRub/confirmBillable |
| `status` | Прочитать небольшую сводку задания | Не получает выдачу у Яндекса |
| `itemsPage` | Показать состояния/номера операций | До 100 строк; query/raw не входят в краткий ответ |
| `pause`, `resume` | Приостановить/возобновить локальную очередь | Не отменяет принятую сервером операцию |
| `cancelPending` | Отменить только неотправленные элементы | Известные операции и результаты сохраняются |
| `normalizeSaved` | Повторно разобрать один сохранённый ответ | `jobId` + `index`; без POST/GET, без нового rawData из чата |
| `exportPage` | Подготовить JSON-файл через файловый механизм | До 25 элементов и 16 MiB на файл; продолжение требует revision |

Предусмотренные сетевые действия: `submit`/`collect` — по одному элементу; `submitN`/`collectN` — до 25; `collectReady` — псевдоним ограниченного `collectN`, **не** выгрузка всех готовых результатов. Сейчас они заблокированы отсутствующим host permission. Время начала новых шагов одной команды ограничено 10 секундами; уже начатый сетевой запрос имеет отдельный таймаут. Нельзя обещать выполнение всех 25 элементов одним нажатием.

## Лимиты и результат

Унаследованный валидатор проверяет 400 Unicode-кодовых точек и 40 частей, разделённых пробельными символами. Подсчёт частей — локальное правило, не доказательство точного алгоритма разбора слов на сервере.

Параметры группировки: до 100 групп и до 3 документов в группе. По документации Яндекса возвращается **не более 250 результатов**, а не гарантированные 300. Валидные параметры не уменьшаются молча. Формат текущего адаптера — XML; period/metadata/userAgent/HTML не выставлены в этом протоколе.

Исходный ответ сохраняется до успешного завершения разбора. Повреждённый XML не считается пустой выдачей. Для сохранённого PARSE_FAILED повторный разбор использует прежние данные; он не восстанавливает отсутствующее содержимое предположениями.

Отправка возвращает номер Operation; результат получают отдельно. Документация указывает минимум 5 минут обработки и максимум 12 часов хранения. Точное время удаления расширение не вычисляет и не обещает; в ручном режиме к получению требуется вернуться самостоятельно. Локальная оценка стоимости не является счётом провайдера.

## Файловая доставка

Экспорт читает последовательные элементы с проверкой revision, а не весь массив задания одновременно. Слишком большой отдельный элемент вызывает явную ошибку без усечения исходных данных. Файл сохраняется бинарными частями через Patch A; в чат передаётся краткая сводка и дескриптор доставки, а не raw-массив. Это описание пути кода; фактическое прикрепление и загрузка в ChatGPT требуют браузерной проверки.
